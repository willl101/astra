# Agent Note: 主动屏幕观察器

Status: implemented

[English](2026-08-29-proactive-screen-observer.md) | 中文

## 问题

个人主动助手需要足够的跨应用上下文来发现有价值的时机，同时不能采集键盘、逐应用适配、持续调用模型或频繁打扰。把原始截图发送给多模态模型会增加成本与披露，而普通 Harness Session 和 attachment 持久化对模型可见输入的保留时间也超过了此类敏感环境上下文的需要。

## 决策

私有 `@deepseek-ai/dsh-experimental-proactive-screen` 插件以用户选择的频率执行 macOS ScreenCaptureKit 截图。helper 截取显示器最终合成画面中裁切到前台窗口的区域、对每一帧在内存中运行 Apple Vision OCR、抑制已知敏感应用，并输出受长度限制的文本 episode。它不写入截图或 OCR 文件。后续的[合成前台屏幕上下文决策](2026-08-31-composed-foreground-screen-context.zh.md)替代了最初的独立窗口与视觉变化门槛。

Host 插件只抑制同应用连续完全相同的 OCR 与和近期已通知任务显著重合的内容，再以关闭 reasoning 的方式唤醒一个克制的 Harness agent。执行模式为被动与主动触发都挂载 standard 工具集；陪伴模式不挂载执行工具。一段精简策略把被动感知定义为：除非当前介入具有明确实际价值或情绪价值，否则严格返回 `0`；把主动触发定义为：只给出一项具体结果，确实无法判断时才问一个必要问题。模型最后一段文字直接视为通知，因此画面复述、内部思考、计划与工具叙述在两种模式下都无效。Host 会拒绝泄漏的过程分析，并只对一次格式错误的主动结果重试。其他助手或开发工具中可见的请求与正常进度属于已在处理的工作，屏幕上可见的实现代码也不能授权 Agent 检查或修改自身。

被动请求与主动决策都使用随机瞬时 Session，并在每次完整决策结束后释放。主动行动默认 Fn×2；输入指令默认 Fn + Space，并打开屏幕下方中央仅含输入框的浮层。两个快捷键通过同一录入器独立配置，并拒绝 macOS、其他应用与彼此的冲突。有效 Accessibility 选区会成为完整模型上下文并抑制截图；输入文字成为首要意图，不存在选区时回退到前台截图。取消浮层不会发起模型请求。每次通知后的继续对话都会把受限本地记录交给独立瞬时 Session，因此一次慢对话不会阻塞后续消息。OCR、选区与输入指令存在于进程、provider 传输与适用的 Harness Session 策略中，而控制台日志只保留应用身份、字符数、已接受的决策元数据、token 用量与提醒文案。严格静默不会进入控制台活动流。

一个全局“允许主动编辑”开关控制被动感知与两个主动入口中的原生 `write_to_editor` 工具。对于明确的编辑指令，如果 Agent 漏调工具，Host 会提取准确的最终正文并通过同一桥接写入。控制台首先恢复主动浮层取得焦点前捕获的不透明 Accessibility 编辑目标与范围；该位置已变化或拒绝修改时，再捕获并写入当前可编辑区域。每个目标都先尝试 Accessibility 直接写入，失败时保存剪贴板全部表示、把 Command-V 只发送给所选进程并恢复剪贴板。被动写回只允许负面影响可忽略的小型客观高置信修正；主动选区或输入指令提供更强编辑意图，但不授权杜撰承诺、个人立场、发送或提交。Node 工具等待带版本的原生动作结果，只有控制台接受写入后才报告成功。

密码管理器、macOS 凭据与身份验证应用以及控制台自身默认被屏蔽。ChatGPT 与 Codex 和其他前台应用一样可被观察；屏蔽控制台自身可阻止直接自反馈。模型接收不可信 OCR framing。执行 Agent 使用中性的临时工作区，Agent 级工具 guard 会拒绝访问观察器仓库或已安装实现；委派子 Agent 与工作流循环不开放，因为它们的工具调用不会继承这项父级 guard。开启执行后，意图明确的低风险可恢复工作可以自主完成。发送、提交、删除或覆盖、发布、付款以及账户、安全、隐私或权限变更需要一次精简确认；用户在后续对话中明确同意该操作后，agent 会执行它。

可选的 `主动 AI.app` 控制台只管理一个 Harness 子进程，并提供打开、关闭、60、15、5、1 秒四档感知、执行与主动编辑开关、两个可配置主动快捷键、通知测试、可折叠诊断、历史以及从通知继续对话。“输入监控”让快捷键编辑器录入双击 Fn；组合键使用系统热键服务。主动行动在屏幕下方中央显示短暂且不抢焦点的星光；输入指令把同一视觉展开为不激活 App 的纯输入面板，该面板成为 key window 但不会显示控制台，回车提交，Esc 或点击其他位置则取消并关闭。本地继续对话请求允许一轮完整 Agent 处理最多耗时 120 秒。只有控制台显式请求时，插件才会输出带版本的 JSONL 活动与原生动作流。控制台持久化受限的已接受元数据与提醒文案，但不保存截图、选中文字、输入指令、OCR 原文、编辑区文字或模型静默决策；其 bundle id 在本地 OCR 前与模型调用前都会被屏蔽。

## 考虑过的替代方案

**逐应用适配。** 原生 API 能为邮件、备忘录、浏览器与聊天提供更高质量语义，但其权限、schema 与维护成本不适合通用个人 demo。

**环境键盘与 accessibility 采集。** 持续事件采集可以改善时机，但会采集风险更高的输入并需要应用特定解释。控制台只观察配置的快捷键，并在该次明确请求后读取一个选中文字值；被动感知仍然只使用截图。

**只使用 Accessibility 直接写入。** 直接设置属性不使用剪贴板，但在许多浏览器与 Electron 编辑器中失败。保留剪贴板的模拟粘贴仍是更通用的回退，其按键只发给选定编辑区所属的进程。

**定期上传截图。** 直接多模态请求能移除本地 OCR 代码，但会消耗图像 token、披露像素，并依赖支持图片的模型。选定的 DeepSeek Flash 路由只支持文本。

**持久化 Session 日志。** 记录精确 OCR prompt 可以恢复普通 Harness 的回放、compaction 与审计行为，但 append-only 持久化与环境屏幕数据最小化冲突。实验插件明确记录回放缺口，而不保留敏感文本。

**仅通知 agent。** 只通知的第一版能最小化权限，但无法查询或完成有价值的本地工作。因此控制台提供一个明确的执行能力开关，同时 agent 策略仍严格限制被动权限。

## 后果

一条通用观察路径可覆盖可见的 macOS 前台窗口。本地 OCR 没有 provider 费用；完全相同画面与近期通知去重不消耗模型 token，其他非空屏幕上下文都会在固定输出上限下进入 agent。截图与 OCR 文本不会在磁盘累积，严格输出 `0` 的静默也不会进入控制台活动流。

控制台具有独立的 macOS“屏幕录制”身份，需要用户明确授权一次。受限活动历史会保留通过的提醒文案，直到用户清空；这以少量本地审计记录换取更方便的测试，同时不保留产生决策的环境输入。

观察器可能误解 OCR、遗漏非文本状态，并可能披露未屏蔽敏感窗口中的文字。它没有持久提醒、未来唤醒或移动端定位来源。被动 Session 被刻意缩短生命周期，因此调试环境决策需使用显式本地诊断模式，并接受由此产生的临时候选披露。

原生写回覆盖大多数可访问文本框，但仍是尽力支持。安全、受保护、Canvas 与不暴露 Accessibility 的编辑器会拒绝修改。捕获位置始终优先；不可用时，当前可编辑区域是明确兜底。
