# Agent Note: 合成前台屏幕上下文

Status: implemented

[English](2026-08-31-composed-foreground-screen-context.md) | 中文

## 问题

独立应用窗口截图可能遗漏显示器最终合成的像素。确定性的图片变化、最少文字、增量文字、相似度与冷却门槛也可能在 agent 判断之前丢弃有价值的短内容或渐进变化内容。屏蔽 ChatGPT 与 Codex 不符合通用前台助手的目标，而控制台已有可以直接屏蔽的独立自身应用身份。

## 决策

截取显示器最终合成画面中裁切到前台应用最大可见 layer-zero 窗口的像素。这仍是前台区域截图而非整个显示器上传；对于允许共享的窗口，不需要逐应用专用路径。对每个按计划截取的帧运行本地 Vision OCR。

使用 ScreenCaptureKit 的第一个完整合成帧。通用循环不加入逐应用重试、稳定判断或多帧选择。

调用模型前，只抑制同应用连续完全相同的 OCR 指纹，以及与最近已投递通知显著重合的屏幕内容。其他非空、受长度限制的当前画面 OCR 全部完整发送给 agent。将稳定的价值与静默策略注册为 Agent 作用域的 system prompt，OCR 则保持为不可信的 user 层观察。由该策略而非确定性 Host 启发式判断当前上下文是否具有足够实际价值或真实情绪价值，值得输出或行动；严格 `0` 仍表示被动静默。作为协议安全网，被动返回如果只是复述屏幕或解释“没有可行动价值”，会归一为同样的静默结果。

继续屏蔽凭据应用、密码管理器、macOS 身份验证界面、通知中心与控制台自身。通知中心被排除，是因为助手刚投递的通知绝不能再次成为模型的新上下文。ChatGPT、Codex、浏览器、文档编辑器、飞书和其他普通前台应用都经过同一条截图路径。截图前检查前台窗口的 CoreGraphics 共享状态；若窗口声明 `kCGWindowSharingNone`，被动感知直接跳过；明确请求则截取窗口所在整块屏幕并标记受保护前台内容缺失。模型使用用户指令与其他可见上下文继续处理，不向用户暴露技术限制，也不把其他区域当成前台应用内容。

Fn 主动请求在与被动工作相互独立、内部串行的主动通道运行，因此用户请求不会被后续环境帧覆盖，也不必等待正在执行的被动 Agent 回合。每个回合仍是瞬时的。通知后续对话只携带原提醒与最近六条明确对话，使用户可以持续交流而不产生无界模型上下文。

## 考虑过的替代方案

**截取整个显示器。** 这会包含无关窗口、菜单栏内容、通知与更多私人文字，却不能改善通常的前台任务。

**维护逐应用截图适配。** 进程族过滤可以修复一种渲染架构，但会为每个例外应用增加脆弱的 bundle 与窗口规则。

**保留确定性的价值门槛。** 图片距离、最少字符、增量字符、相似度和时间门槛能减少调用，却无法区分有价值的短消息与低价值的长文本；它们会在 agent 应用产品策略前拒绝上下文。

**继续屏蔽 ChatGPT 与 Codex。** 这会阻止有价值的跨助手与开发上下文。继续屏蔽控制台 bundle 已足以阻断直接的通知面板反馈回路。

## 后果

允许共享的 Word、飞书、浏览器、ChatGPT、Codex 与其他普通前台窗口使用同一种截图实现。短文字、滚动页面、闪烁光标与细微变化都可以进入 agent。同应用连续完全相同的 OCR 与近期通知重合仍会避免最明确的重复调用。

应用可以强制设置不可共享的截图边界。通用观察器在被动模式下跳过该平台信号，在主动请求时使用带缺失标记的整屏回退，不携带逐应用截图行为。

OCR 会按每个所选间隔运行，更多非空画面可能调用模型，尤其在 Focus 与 High 档。成本与打扰控制被有意交给完全相同去重、受限输入输出、克制策略与单 token 的 `0` 静默。前台区域内由显示器合成的浮层也会被包含。bundle 与名称 block list 仍是隐私启发式，而不是页面级安全边界。
